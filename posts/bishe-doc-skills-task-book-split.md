毕设文档技能包 bishe-doc-skills 今天升到了 0.2.0（提交 651c0cc）。以前开题报告技能叫「开题报告 / 任务书」，正文里只有一小段任务书说明，大致是「任务书比开题报告短，通常包括设计内容与要求、主要技术指标、进度、参考资料」。学校把任务书和开题报告分成两份表的时候，这么写很容易让人直接把开题报告整篇粘过去。这次把任务书拆成独立技能 `task-book`，并补上中期检查技能 `midterm-check`。技能数从 7 个变成 9 个。package.json 里的版本是 0.2.0，没有打 git tag，也没有发 GitHub Release。

我今天在 Node v24.22.1 下对着这个提交跑官方测试，校验输出是「9 个技能校验通过」，后面 21 条安装器测试全绿；GitHub Actions 的 Node 18、20、22 也通过（run 45677137148）。下面说的内容，依据是技能原文、以及我在干净临时目录里实际写出来的文件。各校任务书和中期检查表不一样，我没有拿某一所学院的正式表格或盖章流程核对过。

## 任务书不是开题报告的缩写

旧版 `thesis-proposal/SKILL.md` 的标题就是「开题报告 / 任务书」，任务书只作为开题技能的一节。新版把这件事写清楚了：任务书是学院或指导教师下达的「要完成什么、做到什么程度、何时完成」，偏任务与验收；开题报告才是学生论证「为什么做、怎么做」。开题技能现在会把填写任务书的工作交给 `task-book`，不要把开题报告整篇复制进任务书。

`task-book` 里还有几条很具体的约束。只填学校模板里已经有的栏目，学校没有的不要自己加。学生信息、学号、指导教师姓名只使用用户提供的内容。技术指标必须可检查，比如「支持管理员、教师、学生 3 种角色，权限不可互相越权」，不要写「国内领先」「性能最优」这种无法验收的句子。任务条目和指标要能对上：写了「用户管理」，指标里就要有可验收的权限或功能描述。如果用户已经有代码，先用 `code-to-thesis` 核对真实模块，再写进任务书，避免任务书写了系统里没有的东西。

红线也很明确：不代写指导教师意见、签字、教研室或学院审批意见；不编造课题编号、下达日期、学时、学院盖章内容。任务书写完后，还是要交给指导教师审核再打印或提交。这套技能是整理和表达自己工作的辅助，不是代写工具，也要遵守学校关于 AI 辅助写作的规定。

## 默认一次安装是 28 个文件

在一个干净的临时目录里跑 `node bin/cli.js --dir <项目目录>`（和 `npx -y github:MsNan/bishe-doc-skills` 是同一条入口），输出是：

```
✅ 已写入 28 个文件（工具: claude, cursor, trae, codex，技能: 9 个）
ℹ️  未写入 .cursor/skills：按 Cursor 官方文档，Cursor 会从 .claude/skills/ 和 .agents/skills/ 加载技能（https://cursor.com/docs/skills）。只需 Cursor 时请用 --tool cursor。
ℹ️  同时安装了 Claude 与 Codex 技能目录时，Cursor 可能把同一技能显示两次；主要用 Cursor 请改用 --tool cursor。
```

这 28 个文件是 9 个技能分别写到 `.claude/skills`、`.agents/skills`、`.trae/skills`，再加上一份 `AGENTS.md`。项目目录里没有 `.cursor`。我抽查了刚写出的 `task-book/SKILL.md` 和 `midterm-check/SKILL.md`，三份内容分别完全一样。`task-book` 的开头是：

```
---
name: task-book
description: "毕业设计任务书写作（课题任务与要求、可量化技术指标、应完成成果、进度安排、主要参考资料）。填写或修订学校下发的任务书、把开题内容改写成任务书栏目时使用。"
---
# 毕业设计任务书
```

安装器会把 description 写成带双引号的 YAML 字符串，这和源文件里不带引号的写法略有不同，内容是一样的。`AGENTS.md` 的索引里现在也能看到 `task-book` 和 `midterm-check`，并提醒写中期材料前先读对应技能。默认同时写 Claude 与 Codex 目录，按 Cursor 文档这两处都可能被加载，同一技能也许会显示两次；只需 Cursor 时用 `--tool cursor`。我没有打开真实的 Cursor、Claude Code、Trae 或 Codex 窗口去数它到底加载了几份。

中期检查技能是另一件事：对照任务书如实写进度，不要把计划写成已经完成。这一篇只把任务书为什么要独立出来讲清楚，中期检查的进度表和红线我另外写了。
