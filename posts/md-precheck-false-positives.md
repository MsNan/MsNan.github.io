md-multi-format 最近加了个小功能：粘贴 Markdown 后，预览区下面会出一个"发布前检查"面板，提示标题党用语、绝对化用语、篇幅过短、外链过多和引流话术。几个设计约束是我自己定的：不联网、不接敏感词大库、不调 LLM，只用一份短名单加几条正则；结果只是提示，不拦复制；只有"标题党"算 `error`，其余都是 `warn`。

规则写完、45 条单测全绿以后，我做了一件早该做的事：拿自己以前发过的文章正文去跑。下面的结论都基于仓库 HEAD `061854a` 的 `src/core/precheck.js`，Node 24.22.1，复现脚本直接 import 这个文件。

## 先看真实数据：40 篇旧文跑出来的结果

我手头有 40 篇已发布文章的正文草稿（`*-body.md`，大部分不含标题行，标题是在编辑器里单独填的）。跑一遍，各规则命中篇数：

```text
共 40 篇；标题不是第一行 H1、却被取到「标题」的：9 篇
各规则命中篇数： {"title-empty":25,"title-too-short":2}
```

`title-empty` 25 篇是预期内的，正文里本来就没有标题。真正的问题是那 9 篇，它们取到的"标题"是这些：

```text
标题取成了「tests 5」
标题取成了「pass 1」
标题取成了「fake_llm.py」
标题取成了「我的项目规则」
标题取成了「0. ops 现在能发公告吗」
……
```

全是代码块里的东西：`node --test` 输出里的 `# tests 5`、`# pass 1`，Python 文件开头的 `# fake_llm.py` 注释，shell 片段里的 `#` 注释，还有一段 AGENTS.md 示例输出里的一级标题。而另外几条规则（绝对化、引流）在这 40 篇上一次都没响。真实文章里最先出问题的，不是我花时间最多的那几张词表，而是一个看起来最简单的函数。

## 1. 取标题时没跳过代码块

```js
export function extractFirstH1(md) {
  const body = stripFrontMatter(md.replace(/\r\n?/g, '\n'))
  const m = body.match(/^#\s+(.+)$/m)
  return m ? m[1].trim() : ''
}
```

同一个文件里其实已经有 `stripCodeFences`，其他规则都用了，只有取标题这里漏了。漏掉的后果不只是"标题显示错"。标题会接着去过标题党名单，比如一篇没有 H1 的安装教程：

````md
## 安装

```bash
# 震惊 这一步必看
npm i
```
````

```text
extractFirstH1 = "震惊 这一步必看"
ok=false  issues: title-bait(震惊 这一步必看)
```

整个检查里唯一的 `error` 被一行 bash 注释触发了，`ok` 变成 `false`。界面上 `App.vue` 也是用 `extractFirstH1(text)` 取标题，面板会挂一个红色的"问题"标签。

修法：先去代码块再匹配；顺便按 CommonMark 允许最多 3 个空格缩进，去掉 `# 标题 ##` 这种结尾的闭合 `#`。

## 2. 行内代码没剥掉

围栏代码块被排除了，但行内代码没有，于是：

```text
开头写 `width: 100%`                      → absolute-claim(100%)
正文里写 `'扫码进群'` 这种字符串会被命中   → promo-drain(扫码进群)
8 个写在行内代码里的接口地址               → too-many-links
```

第一条最冤：讲表格横向滚动的文章，第一段就是 `width: 100%`。行内代码本来就是"原样展示的代码"，和围栏代码块是一回事，三条规则在匹配前都应该先把它剥掉。

## 3. 短词名单：误伤技术词，又漏掉变体

绝对化用语的正则里有个单独的 `保证`，引流的正则里有个单独的 `二维码`，还有 `微信\s*[:：]\s*\w`：

```text
"用事务保证数据一致性。"          → absolute-claim(保证)
"# 用 qrcode 生成二维码"          → promo-drain(二维码)
"微信：wx.login 拿 code"           → promo-drain(微信：w)
"源码加V领取，+v：abc123，威信同号" → (无)
```

技术文章里"保证一致性""保证顺序"太常见了，讲二维码生成库的文章也不少；反过来，真正的引流常用"加V""威信"来绕关键词，名单里一个都没有。

短名单本身没错，我不想接词库。但名单里的词要带上下文：`保证` 只在"保证学会/保证你/保证能"时才算；`二维码` 要和"扫/加/关注/领取"连起来才算；`微信：` 后面要跟一个像微信号的串（字母开头、6–20 位、后面不接 `.`），`wx.login` 就不会命中。再补上"加V"（后面不能接字母，免得把"加 Vue"误伤）、"威信"、"+v："。

## 4. 裸链接把中文标点吃进去了

```js
const BARE_URL = /(?<![\("'])https?:\/\/[^\s<>\)\]"'`]+/gi
```

中文正文里，链接后面紧跟的往往是全角标点，没有空格：

```text
文档：https://example.com/docs/precheck。也可以看 https://example.com/docs/precheck，以及 https://example.com/docs/precheck）
→ xhs-outbound-link：3 个外链
  https://example.com/docs/precheck。也可以看
  https://example.com/docs/precheck，以及
  https://example.com/docs/precheck）
```

同一个地址被当成 3 个不同的 URL，去重失效，"外链 ≥8"这条阈值也会被提前触发。修法是在字符类里排除 CJK 字符、CJK 标点和全角符号。代价是路径里直接写中文的 URL 会被截断，但它只影响计数，不影响渲染。

## 5. "字数"按字母算

```js
const m = cleaned.match(/[\u4e00-\u9fffA-Za-z0-9]/g)
```

汉字一个算 1，英文**每个字母**也算 1，裸 URL 的字母也算进去了：

```text
8 句英文（64 个词）       → 不报篇幅过短
4 空格缩进的 400 个 x     → 不报篇幅过短（只排除了围栏代码块）
```

更有意思的是仓库自己的测试夹具：`longBody()` 生成的"正常正文"加上标题，按这个口径算是 247 字，低于 250。"干净标题不报标题党"那条用例其实也带着一个 `body-too-short`，只是测试没断言这一条，所以一直没人发现。

改成中文写作里常用的口径：汉字一个算 1，英文单词或数字串整体算 1，去掉裸 URL 和缩进代码。改完那 64 个英文词就是 66 字（加上标题里的 2 个词），会正常报过短。阈值 250 我没动。

## 6. 代码块没闭合，后面的内容全部消失

````text
……正文……
```js
console.log(1)

加微信领取完整源码
````

围栏开了没关，`stripCodeFences` 会把后面的所有内容当成代码跳过，引流话术就这样躲过去了，结果是 `(无)`。按 CommonMark，未闭合的围栏本来就会延续到文末，渲染出来确实是一整块代码，所以这里不该假装它是正文去查。但"后半篇都变成代码块"本身就是发布前最该提醒的事。补了一条 `unclosed-fence` 警告。

## 没改的

- **Setext 标题**（下一行写 `===`）不识别：这个项目的小红书卡片把单独一行 `===` 当作手动分页符，两种语义冲突，取标题这里先不碰。
- **front matter 里的 `title:`** 不读：编辑器里标题本来就是单独填的，界面也没有传 title 的入口。
- **绝对化用语只看标题和开头 200 字**：这是故意的。正文中间出现"保证"多半是在讲技术，开头和标题才是"承诺读者"的位置。
- **`ok` 只看 `error`**：引流、过短、绝对化同时命中，`ok` 仍然是 `true`。这也是故意的，面板只做提示，不拦复制。

## 补丁和验证

改动只在 `src/core/precheck.js` 和 `test/precheck.test.js`，本地验证，没合入仓库：

```text
vitest：45 → 51 条，全绿
40 篇旧文：从代码块取到"标题"的 9 → 0 篇
构造用例：保证一致性、width: 100%、二维码、微信：wx.login、行内代码里的引流词都不再误报；"加V"能报；未闭合围栏有提示；同一 URL 去重为 1 个
```

这次最大的收获是：规则写完先拿自己的历史文章跑一遍，比再多写十条单测都管用。单测里的样本是我想象出来的文章，历史文章才是我真正会粘贴进去的东西，里面有 `node --test` 的输出、有 Python 注释，也有示例 Markdown。

顺带一提，这篇文章自己也过不了检查：补丁前因为提到「二维码」报疑似引流，补丁后因为正文在讨论「加V」还是报。这正是它只给 `warn` 的原因，规则看不懂上下文，最后还得人来判断。
